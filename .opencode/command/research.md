# Research Command

Perform deep research and analysis on any topic, system, or problem.

## Usage

```
/research <topic>
```

Where `<topic>` can be:
- A technology or framework
- A problem or issue
- A codebase or system
- A best practice or pattern

## Research Process

1. **Define**: Clarify research scope and questions
2. **Gather**: Collect information from multiple sources
3. **Analyze**: Identify patterns and insights
4. **Synthesize**: Create actionable summary
5. **Report**: Present findings with evidence

## Research Areas

### Codebase Analysis
- Project structure and architecture
- Patterns and conventions
- Dependencies and relationships
- Issues and opportunities

### Technology Research
- Framework comparisons
- Library evaluations
- Best practices
- Case studies

### Problem Investigation
- Root cause analysis
- Impact assessment
- Solution options
- Prevention strategies

## Output Format

### Executive Summary
Brief overview of key findings

### Detailed Findings
- Point 1 with evidence
- Point 2 with evidence
- Point 3 with evidence

### Recommendations
Based on findings, what should be done

### Sources
References and citations

## Research Templates

### Technology Evaluation
```
## Technology: [Name]

### Overview
[What it is]

### Pros
[Advantages]

### Cons
[Disadvantages]

### Use Cases
[When to use]

### Alternatives
[Comparable options]

### Recommendation
[Your assessment]
```

### Problem Investigation
```
## Problem: [Description]

### Symptoms
[What was observed]

### Root Cause
[Why it happened]

### Impact
[What was affected]

### Solution
[How to fix]

### Prevention
[How to avoid]
```

## Examples

```
/research React vs Vue
/research memory leak in Node.js
/research authentication best practices
/research ./src architecture
```

## Integration

This command uses the Bahram Researcher subagent. For code review, use the `/review` command. For deployment, use the `/deploy` command.
